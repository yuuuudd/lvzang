# 产品目标与设计

## 目标与用户

旅藏：Agent帮助游客体验地方文化，并把旅行变成自己的3D纪念收藏与个人展览。

优先验证有纪念意义的结伴旅行者，例如毕业、情侣和朋友旅行；文化街区与博物馆爱好者为扩展用户。商家先定位为地方文创店、文化体验空间与打印供应方。暂不覆盖所有游客、所有城市、所有票务交易。

用户价值：更容易理解地方文化；更省事地保存自己的旅行记忆；能分享一份完整作品，并可选定制实体纪念品。数字3D收藏应包含个人照片、日期、故事等记忆，不能只是所有人都相同的模型。

这些是待验证的价值假设，不是已证明的付费需求。首轮找10—15名近期真实出游者试用，再接触1—2家相关商家；观察是否主动完成、保存、分享，是否具体询问定制，不能只记录口头好评。

## 两条入口

正在旅行：选择文化主题 → 对话补充时间/兴趣/同行情况 → 主题路线 → 地点故事与照片记录 → 3D收藏 → 旅行展览。

已经旅行回来：选择地点或导入照片 → 整理经历 → 选择预制或个人定制3D作品 → 旅行展览。

两条入口都可进入：分享 → 选择一件作品 → 提交定制需求 → 商家报价 → 线下确认打样与交付。

不要求完成规划、签到或集齐模型才可制作展览。交通天气帮助路线可执行，航班出票、酒店交易和全品类商城不作为第一版主线。

## Agent分工

- DeepSeek对话：自然回答问题、理解意图、记住用户条件，不把每句话都变成路线。
- 需求整合：维护需求档案，合并本轮修改，保留未修改条件，识别冲突。
- 路线与资料：组织文化主题，整合可选攻略，以可靠资料支撑故事；之后接入真实交通与天气。
- 展览整理（待做）：把用户照片和经历整理成收藏文案与展览叙事，不杜撰用户经历。
- 定制整理（待做）：整理尺寸、材料、文字、作品信息，生成商家能处理的需求单。
- 校验：检查同城、时长、排除/必去要求、依据与未确认事项。

Agent按任务触发，不要求每条聊天都调用多个模型。画面显示实际处理阶段和具体修改，而不是假的完成进度。

## 需求档案设计（待做）

分为已明确、暂定、待补充：目的地；日期与天数及每日可用时段；抵离与起终点；同行人数和老人/孩子；预算口径；兴趣和纪念主题；步行与交通偏好；必去与避开；住宿区域；饮食限制。每轮最多追问1—2项关键缺口，允许先推荐与稍后补充。

日程应按每日组织，不把三天直接压成单个总小时数。参观时长问题不等于请求改变整趟旅行时长。

## 视觉与信息架构

沿用已认可的固定产品风格：浅灰/白、炭黑文字、黄绿色操作强调、统一图标。左侧连续对话，右侧可移动缩放的画布，移动端堆叠。Agent不按旅行主题重新生成UI。

当前广州插画是示意素材；标签和路线交互覆盖。未接真实高德导航，其他城市只有地点相对位置或路线顺序示意。不得把插画位置当真实交通坐标。

下一版重点把个人收藏和展览提高到核心成果位置。已有3D预制模型可快速展示；个人定制复用原创作入口。所有预制物都应有真实文化资料和来源，不声称精确文物复原或已打印认证。

## 第一版范围

以广州一个主题案例、三件现有纪念品、一家示范商家跑通完整链路。数字体验可独立完成，打印是可选。实体打样至少明确规格、报价、样品结果；现有报价只是本机记录，付款和供应方履约未实现。

暂缓：全量票务、完整酒店交易、全国铺开、供应商自动比价、强制签到与排行榜。
