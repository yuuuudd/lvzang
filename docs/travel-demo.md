# 旅藏 · 拾光文旅模块演示说明

旅藏把旅行规划、沿途探索、3D 纪念品收藏和文创定制放在同一条体验链路中。产品面向游客；商家通过主题活动进入游客的规划入口，并承接纪念品定制需求。产品使用统一的微缩世界视觉，Agent 负责分析与规划。

## 启动与入口

在项目目录运行 `npm install` 和 `npm start`，打开 `http://localhost:4173/travel.html`。原来的拾光创作室 `/`、简洁版 `/simple.html` 都保留，页面之间可互相进入。

当前展示服务另开在 `http://localhost:4180/travel.html`。重新启动使用 4180 时，在 PowerShell 中先执行 `$env:PORT='4180'`，再执行 `npm start`。

本地策划模式不需要密钥。真实 Agent 协作和截图读取使用服务端 `.env` 中的 `DEEPSEEK_API_KEY`，不会将密钥发给浏览器。选择 AI 协作后，每次策划调用三个文字阶段；读取截图额外调用一次视觉接口。原创纪念品的付费生图和建模沿用拾光入口，由用户另行发起。

## 三分钟演示

1. **没有攻略，也能开始。** 打开探索旅行，不填写内容，点击“帮我安排”，展示默认方向、主题推荐和未确定的条件。也可以直接选择一张主题卡。
2. **逐步补充需求。** 输入“苏州半天，和父母出游，喜欢园林和建筑，希望少走路”。可选导入攻略正文或截图；链接仅保存为出处。选择 AI Agent 协作，展开协作记录，展示不同职责与总控校验。
3. **新的条件修正方案。** 改为“杭州两小时，喜欢风景，希望少走路”，重新策划；最新文字里的城市和时间会覆盖旧表单条件。导入攻略仍保留，但不会把苏州地点混入杭州行程。
4. **旅行带来收藏。** 点击地点卡中的“模拟签到 · 解锁”，拖动真实三维模型，写下旅行故事。关闭后在“我的展柜”查看，刷新仍可恢复；可排序、命名、导出备份。
5. **收藏带来传播。** 点击“分享我的展览”，在另一个浏览器打开只读展柜。链接只携带展品、日期和故事，不携带攻略、照片或定制需求。本地地址只能在本机演示；外部分享需要先部署到可访问的地址。
6. **纪念品进入服务链路。** 在纪念品详情设置宽度、材料、定制文字，下载 STL 或提交定制需求。切到商家工作台，录入供应商、价格、交期与费用说明，比较多个报价；重复需求与相同报价不会重复计数。
7. **商家获得推广入口。** 商家保存一个“苏州手作探索”活动。游客的主题推荐中出现该活动，点击后结合需求策划路线。现场核验与工厂履约仍是后续接入项。

## Agent 如何工作

| 阶段 | 输入与职责 | 可看到的结果 |
| --- | --- | --- |
| 资料 Agent | 可选攻略、策划地点库；整理观点与待核实内容 | 资料摘要、原帖片段、出处与地点关联 |
| 偏好研判 Agent | 城市、时长、兴趣、同行情况与最新需求 | 候选地点和筛选理由 |
| 路线 Agent | 已筛选地点；组织顺序与行程提案 | 路线主题、顺序和理由 |
| 总控规则 | 校验地点白名单、城市、时间与出行节奏 | 可执行的最终路线；提案被缩减时明确说明 |

前三个阶段在真实 AI 模式中分别调用模型。总控使用代码校验。本地模式采用地方资料和规则，界面明确显示“未调用真实 AI”。AI 请求失败保留前一方案，不偷偷换成本地结果。

## 比赛版本的商业链路

商家提供主题体验 → 游客获得适合自己的行程 → 探索并收藏 3D 纪念品 → 分享个人展馆传播目的地 → 游客提出实体定制需求 → 商家比较供应商报价。

收费可先围绕实体制作与定制服务验证；商家主题活动与数字收藏用于获客和传播。当前没有收取费用、承诺利润或声称已有成交。向供应商询价时可以用页面中的尺寸、材料与定制要求；报价需人工获得后录入。本版没有自动爬取供应商、联系工厂或支付接口。

## 当前边界

- 地点资料覆盖苏州、杭州，共 8 个预制风格纪念品。其他城市明确提示范围，不自动替换成苏州；不声称实时搜索或核实了营业、预约、交通与票价。
- 签到是比赛模拟。收藏、活动和定制需求保存在当前浏览器；商家工作台是本机角色切换，没有跨账号交易和云端同步。
- 预制模型是可旋转的三维几何，不是几张照片。STL 是毫米尺度、多部件封闭网格，仍需在切片器合并部件、检查支撑与细节并试打；没有完成实体样品验证。
- 定制文字仅进入需求记录，尚未刻入预制模型。照片定制入口进入已有拾光创作流程，不自动付费生成。
- 原帖真实性、广告识别与受限平台自动抓取不在本版。截图只转录可读文字，需用户核对后加入资料。
- 海报是产品视觉概念；海报中细致的模型表现不代表当前预制几何的细节精度。海报保存于 `artifacts/posters/travel-poster-2026-10-04.png`。

## 验证与证据

`npm test` 运行整个项目的基础、服务与三维导出检查。`node tests/travel.browser.js` 在 Chrome 中验证空输入、导入、需求修订、WebGL、STL 下载、收藏刷新、跨浏览器分享、商家报价、活动、损坏存储保护及桌面/移动布局，不使用付费 API。

`node tests/travel.live.js --allow-live` 是可选的真实调用检查，需要本地服务运行在 4180 和现有文字/视觉凭据，会产生 API 费用；普通 `npm test` 不运行它。它使用演示文字截图，验证 OCR、苏州规划及改为杭州两小时后的修订，不调用付费生图或建模。也可通过 `TRAVEL_TEST_ORIGIN` 指定服务地址。

当前截图与真实接口结果保存在 git 忽略的 `artifacts/travel/`：`home-desktop.png`、`home-mobile.png`、`collection-desktop.png`、`collection-mobile.png`、`live-integration.json`、`live-ai-route.png`。结果只包含演示输入与路线，不包含凭据。
