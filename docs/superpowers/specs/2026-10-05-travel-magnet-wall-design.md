# 旅藏：地图冰箱贴墙与个人纪念品设计

日期：2026-10-05。依据：用户确认的四张冰箱贴效果图，以及“个人收藏同时包含个人回忆和多人回忆；3D纪念品是核心卖点”的要求。

## 目标与首轮交付

让游客从自己的地图冰箱贴墙进入一件真实可旋转的3D纪念品，翻开照片与故事，再提交明确的实体定制需求。地图墙与收藏柜共用收藏；冰箱贴与微缩摆件共存，不强制把旧摆件变成冰箱贴。

用户最新要求：用第一性原则与对抗性审查做好收藏柜和冰箱贴，先不考虑队友。执行范围锁定为本机个人收藏产品；包含共同旅行的记忆组织，但不建设多人账号或实时协作。多人内容可通过明确标注的演示案例展示，不能把同一浏览器里填写多人姓名称为真实多人协作。真实邀请、跨设备网页分享及商家收单不在本轮范围。

## 第一性原则与优先级

收藏的对象是“与自己有关的一件作品”，不是地图上的城市数量。城市组织作品，独立作品承载旅行，照片与故事提供归属感，真实几何与尺寸帮助判断实物价值。

优先级：一枚有辨识度且能看清侧背面的冰箱贴→创建自己的回忆并可靠保存→柜子与地图组织多件作品→定制规格与可导出文件。最先完成三枚普通作品，不如先把广州一枚做到可用且有吸引力，再扩展杭州、苏州。

入口默认显示地图墙；0件收藏提供创作入口而非空地图；1件作品突出该作品，地图为背景；至少2件后再突出地图墙。收藏柜始终可切换。首轮保留共同回忆作者署名，邀请入口显示接入说明，不做不可用的主按钮。

## 页面与渐进展开规则

1. **地图贴墙入口**：标题“把回忆，贴在走过的地方”；默认地图视图，收藏柜为同级切换。中国地图上展示收藏的3D冰箱贴缩略图，支持缩放、拖动、全部/个人回忆/共同回忆筛选。最近收藏区域只显示作品、标题、日期及参与者，不展开全文故事、照片册、定制表单。没有收藏时展示清楚的添加入口；示例需主动点击，不写入用户收藏。
2. **作品详情页**：模型占桌面主要区域，显示正面、侧面、背面与旋转缩放；右侧仅显示标题、日期、参与者和简短摘要。“翻开这枚冰箱贴的回忆”与“定制实体冰箱贴”分别进入不同弹窗。摆件显示对应品类文案。地图位置、筛选和缩放在返回后恢复。
3. **回忆弹窗**：一页一段记忆，每页照片、日期、地点、作者与故事，支持前后翻页和本机添加/编辑。照片不可覆盖主模型。没有照片也能保存文字回忆。关闭后回到原作品；编辑未保存时给出继续编辑或放弃的选择。
4. **定制弹窗**：展示所选模型的正面、背面和摆放情境；冰箱贴在冰箱上，摆件在桌上。选择尺寸、颜色、数量，填写刻字需求，再提交。第一版只提交询价，不声称已付款、生产或发货。刻字尚未进入几何时，清楚标为需求与效果预览。

详情是独立页面状态，两个弹窗互斥，不做多层弹窗。浏览器后退依次关闭弹窗、返回作品列表。桌面1440×900与手机390×844均可用；手机弹窗改为全屏内容，操作区可达。

## 3D与地图的真实性

- 图片效果图只作为视觉参考；运行界面必须有真实网格与可操作的旋转，不以静态图冒充3D。
- 首轮先完成广州塔与骑楼，再扩展西湖亭、苏州桥与街巷。素材采用成对的透明正视彩稿与独立深度图，轮廓与像素对齐；深度图按底板/水面/建筑/塔身分层，不直接把颜色亮度当几何。复用 `reliefFromImage` 的闭合轮廓及平背逻辑，增加可选高度图；明确这是艺术浮雕，不是建筑精确复原或照片三维重建。正面颜色用纹理；米白版本关闭彩色纹理。素材须可用于项目，不能直接从效果图截取带光影的模型充当生产资产。
- 默认尺寸以**高度**计：50、70、90 mm，默认70 mm；宽度按图案比例推导。预览与STL使用同一网格、同一缩放；内部统一mm。保留旧摆件的宽度规格，避免混用宽与高。
- 本轮冰箱贴平背用于后续粘贴磁铁，不默认增加磁铁孔或显示已安装磁铁。概念图中的磁吸结构不作为已实现承诺。真孔位及磁铁型号由打样确定后再接入制造模块。
- 地图用项目可分发、来源可追溯的完整中国轮廓SVG；保留离岛表达，人工核对轮廓与城市位置。地图是收藏示意，不承担导航。三城锚点使用归一化坐标；其他城市无已核对锚点时进入“待定位”列表，不猜位置。
- 同城多件作品先显示数量及最近一件，点击展开该城列表。地图缩略图用模型生成的静态缩略图，仅详情启动一个WebGL预览；关闭/切换释放资源。

## 数据、兼容与本机边界

新增数据库 `lvzang-keepsakes`（IndexedDB，版本1），存储 `keepsakes`、`memories`、`photos`、`requests`、`meta`。不修改旧 `lvzang.v1` 的结构，不向localStorage或URL写照片。

- `Keepsake`：独立UUID、schemaVersion=1、title、city、placeIds、kind=magnet/miniature、scope=personal/shared、participants（id/name/avatarRef）、日期范围、modelRef、memoryIds、createdAt、updatedAt、origin=user/demo/legacy。
- `Memory`：独立UUID、keepsakeId、authorId、date、placeName、story、photoIds；一件作品可有多段记忆，个人作品默认一位参与者。
- `Photo`：id、blob、mime、width、height。JPEG/PNG/WebP，单张最多10MB、24百万像素，解码后最长边1600像素；首轮每段最多4张、一件最多12段，超限明确提示。
- `Request`：id、keepsakeId、modelRef、模型版本、sizeAxis=height/width、sizeMm、colorMode=color/ivory、quantity=1..20、text（最多20个Unicode字符）、status=local-draft、createdAt。双击提交不重复建单；修改规格后可新增需求。

读取旧收藏只做只读兼容显示，新增数据不覆写旧记录。用户第一次保存旧作品的新增回忆时复制到新库，记录legacy来源ID，保留原摆件及旧故事；同一旧收藏只复制一次。旧分享链接与旧商家需求保持可读。首次打开不自动导入示例或执行收费生成。

照片保存失败、容量不足、模型加载失败均保留可恢复编辑内容，显示真实状态；不弹成功提示。未知模型仍可读故事和规格，显示静态回退，不借用别的城市模型。新增回忆、移除照片和改日期可完成；删除作品前确认，失败不删界面中的旧数据。提供包含照片的完整备份ZIP及恢复，导入保留独立UUID、校验文件与容量，冲突默认跳过并报告，不覆写已有作品。

## 分享与范围外能力

首轮提供导出分享卡PNG（模型缩略图、城市、日期、标题；用户主动选择是否附照片/故事），通过浏览器原生分享或下载；不宣称图片可点击翻页。旧分享链接继续用原协议，明确不含新照片。真实邀请按钮首轮标注“多人协作待接入”，不生成不可用的假链接。

本轮不设计共享服务实施任务。以后需要多人协作时再制定独立计划；独立作品ID及作者字段为其提供数据基础，不提前建设账号/权限框架。

## 实施与成功标准

本计划作为用户这一块的完整工作单，覆盖UI、3D、必要的本机存储与静态资源接入。原分工只作背景，不等待队友接口，不改Agent行为，也不建设商家服务。

首轮完整场景：添加一枚冰箱贴→地图/柜子显示→点击看真实3D→补照片和故事→刷新恢复→翻页→选择规格→本机定制需求→导出分享卡及完整备份→导入恢复。制作意愿由是否主动选规格并具体询价观察，不以点赞数证明。对抗性审查见执行计划的审查表，发现失败先修核心流程，不靠增加页面掩盖。
