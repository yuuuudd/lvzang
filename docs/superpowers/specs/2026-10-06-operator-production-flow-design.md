# 经营者实体制作流程设计

日期：2026-10-06  
状态：视觉方向已确认，待实现

## 目标

经营者页面只解决两件事：用户缺少创作能力时协助完成纪念品设计；用户已有 GLB 时直接承接实体生产。默认最终交付物是实体纪念品，不向普通用户提供 GLB、数字交付包或技术检查文件。

用户上传的是故事与素材，不是专业制作需求。故事从用户端自动同步到委托；尺寸、材料、数量和必要的模型调整由经营者在沟通中整理。

## 两条委托路径

### 需要协助创作

照片与故事 → 参考方案 → 用户确认 → 经营者建模 → 资产确认 → 报价与打样 → 制作 → 实体交付。

确认参考方案前不开始建模。用户只确认外观和故事表达，不接触 GLB、壁厚等技术信息。

### 已有 3D 资产

故事与 GLB → 经营者生产检查 → 必要调整确认 → 报价与打样 → 制作 → 实体交付。

该路径不显示创作工具，不重复生成参考图或模型。

## 页面

1. **委托总览**：按“需要协助创作”和“已有 3D 资产”分流，显示下一项待办，不显示营收看板。
2. **方案沟通**：左侧为自动同步的故事和照片，中间为参考方案版本，右侧为用户反馈与确认状态。主操作是“发送给用户确认”。
3. **生产确认**：显示用户提交的 GLB、同步故事、生产检查、规格、报价与生产进度。主操作是“向用户确认生产调整”或“发送报价与打样方案”。

原“需求与素材 → 制作 → 审核 → 交付”改为与路径相符的步骤。原“选择已有作品”“提交审核”“数字交付包”等入口退出主流程。

## 预设演示委托

首次打开且没有真实委托时提供两条明确标注“演示”的记录：

- “抖音创作者大会”：照片与故事已同步，参考方案等待用户确认。
- “嘉兴夜游纪念摆件”：GLB 与故事已同步，等待生产检查。

演示数据使用现有本地素材或轻量占位内容，不进入真实委托数量、费用或经营统计；用户创建真实委托后仍可单独查看或隐藏演示记录。

## 状态与规则

- 主状态：待沟通、等待用户、待生产确认、待报价、打样中、制作中、待交付、已交付。
- 故事保留原文，并显示“已从用户端同步”；经营者整理的生产信息不能覆盖故事。
- 用户确认和经营者生产检查分别记录，不能互相替代。
- GLB 仅为内部生产资产，不作为用户端交付物。
- 页面加载、切换步骤和查看资产不得触发付费生成。

## 实现与验证范围

沿用现有原生 HTML、CSS、JavaScript、IndexedDB/本地存储和模型预览能力，不增加依赖或第二套存储。优先修改现有经营者渲染与领域状态，复用已有安全转义、模型查看和持久化逻辑。

验证覆盖两条演示路径、故事同步标签、路径专属操作、用户确认前不建模，以及页面中不再出现面向用户的数字交付操作。
