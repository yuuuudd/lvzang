# 旅藏：旅行探索与 3D 收藏实施设计

## 目标与已有基础
以现有拾光 Web/Node 项目为基础，新增可运行的文旅体验入口 /travel.html，保留原始创作、回忆画、历史和打印工具。参赛用户是游客与大学生经营者。成功标准是完整演示推荐、按需求修订、多 Agent 分析、探索解锁、3D 收藏、分享和定制需求管理。

## 已确认的产品要求
- 不要求先导入攻略；空输入提供主题推荐，少量信息给方向，详细条件修正路线。
- 攻略正文、截图是可选输入；不自动抓取受限网站，不判断广告。链接只保存为出处，不声称读过内容。
- 总控协调资料、研判、路线三个专业阶段；可配置 DeepSeek 真实调用，离线资料模式明确标记，不冒充实时检索或 AI。
- 产品美术固定为暖色微缩世界、松绿与珊瑚色、风格化地图和收藏柜。Agent 不设计 UI。
- 预制 3D 纪念品可立即查看、拖动旋转；解锁为比赛现场模拟签到，明确显示。
- 收藏、路线和定制需求本机持久化；分享生成不含个人资料的自包含只读链接，支持跨浏览器读取，不假装云端账号同步。
- 商家端管理本机活动、查看需求和输入真实供应商报价；模拟数据标记清楚。没有支付、真实工厂 API 或正式到访核验时不得显示为已付款、已生产。

## 架构
复用现有 createApp、DeepSeek 配置和 WebGL preview。新增 travel-agent.js 编排服务，/api/travel-plan 提供路线，/api/travel-import 解析截图（真实视觉调用，无配置时报错并允许粘贴正文）。所有模型输出做白名单 ID、来源和时间校验，用户帖子只作为数据。候选地点为有出处的苏州、杭州本地策划资料；现场信息待确认，其他城市可以给方向，但不能被默默替换。详细安排使用同一目的地。

前端模块拆为 catalog、planning/model、state、souvenir-mesh、travel UI。分享通过有界编码 payload，按版本校验、只读。数据存储失败显示提示，页面内容使用 textContent 或转义。打印提供真实 STL 文件导出及原有定制工具入口；生产检查、报价与付款保持未完成状态。

## 验收
1. 空输入推荐，杭州或苏州明确输入不混城市，未知地点给出范围提示。
2. 攻略去重、保留出处、修正需求后路线变化且已有收藏不丢失。
3. 真 AI 模式有不同专业调用与总控检查，非法地点/输出拒绝，失败保留前一方案。
4. 3D 预制模型能旋转与导出；模拟解锁与真实到访明确区分。
5. 收藏刷新恢复，分享跨浏览器可查看且不可修改原收藏。
6. 定制需求可提交、商家可录入报价，取消或重复操作不产生重复需求；无支付承诺。
7. 桌面、移动布局验证，原测试通过，不读取或暴露 API 密钥。
