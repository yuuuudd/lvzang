# 统一登录与双端订单同步

用户已授权直接补齐同一入口登录和用户提交到经营者处理的链路。继承之前“设计文档后直接执行”的授权。

共同入口 `/portal.html`：用户名与密码登录，普通用户注册仅获得用户权限。首次在本机建立工作室账号获得用户与经营者权限，后续用户不能通过页面选项提升权限。角色切换由服务端核对账号实际权限。

用户登录进入现有旅行收藏；“我的订单”进入 `/orders.html`。从合集或作品申请定制先到用户订单表单，带入已有素材；也可直接上传照片填写需求。用户提交后服务端存订单和素材，同步到经营者待审核列表。

经营者登录进入现有工作台，默认显示服务端收到的委托；查看用户已填需求，接受并开始制作，或退回补充。原有人工代录和本机委托保留为次入口。制作复用现有半自动流程，选择的图像和模型上传关联同一服务端订单；用户端看到处理状态、待确认作品和交付文件，可确认或提出修改。

服务端使用现有 Node 与本地持久文件存账号、会话、订单和文件，写入采用串行化及临时文件替换。密码以 scrypt 加盐哈希保存，登录会话使用 HttpOnly/SameSite Cookie，服务端检查身份、角色、订单归属、版本和素材大小。首次工作室初始化限定本机连接；普通注册不能创建经营者。所有新增写接口要求同源。

用户只能读取自己的订单与对外结果；经营者可以处理提交给工作室的订单。内部经营记录、成本和备注不返回用户。照片/模型通过鉴权路径领取，不作为公开静态文件。

现有本机收藏按账号分开；首次工作室账号保留导入原本机资料的兼容能力。收藏尚未全面云同步，提交订单时才上传本单选定素材。订单跨浏览器读取不依赖 IndexedDB；登录用户不同不能看到彼此订单。

测试：两个独立浏览器分别登录用户和经营者；用户提交，经营者收到、接受并制作、上传结果、用户确认、经营者交付；第三用户不能读取该订单或素材，普通用户不能切换到经营者。服务重启后订单、素材和会话仍可恢复。既有无账号测试适配保持原测试范围，生产本机入口启用账号检查。

本轮不新增支付、物流或公网部署；双端用同一可访问服务同步，跨设备访问仍需要把服务部署到两端可访问的地址。
