# 旅藏：持续理解旅行需求

打开 /travel.html，选择 AI Agent 协作模式。服务端使用 .env 中的 DEEPSEEK_API_KEY 与 DEEPSEEK_MODEL。本地示范仍是规则演示，不调用 DeepSeek 或联网攻略工具。

页面顶部的“和 DeepSeek 继续聊”进入对话；“补全旅行偏好”继续询问未确认的需求；“改善当前攻略”让你填写具体反馈，填写后由你发送；“补充详细攻略”沿用当前路线补充游玩和吃饭等信息。这些动作保留原方案和未发送的输入。原有天数、时长与强度设置位于可展开的“调整天数、时间和强度”中。

## 一段连续对话

1. “想去广州玩两天，每天六小时。”——先了解同行情况、热门还是小众、兴趣；随后分轮补齐必去、避开、预算、强度、饮食、住区、出发点、交通和日期，每轮最多三项。
2. “两个人，热门和小众都要，喜欢建筑和美食，必去正佳，不去广州塔。”——只补充本轮明确表达的条件，之前确认的内容继续保留。
3. “每人全程600元，不吃辣，住体育西，公共交通，日期未定，先出方案。”——允许按明确标出的暂定条件起草。天数和每日时间独立保存，不固定为三天。
4. “正佳附近中午吃什么？”——结合已保存的偏好与攻略回答，保留路线。
5. “第二天只玩两小时，14:00开始，轻松一点。”——只调整第二天，其余日期与全程需求保留；每天行程旁能查看具体玩法、餐饮、预约提醒和备选。
6. “预算改为500元。”——保留原有地点和日期，预算继续沿用此前人均／全程口径。

追问直接显示在 DeepSeek 的聊天消息中，分段展示，直接在输入框回答即可，也可以一次只回答一个。需求设置不再重复显示截断的追问小框。手机按“消息 → 输入框”自然排列；查看地图或攻略后可点“继续和旅行顾问聊”。每站也有“问问怎么玩、附近吃什么”入口，策划过程与灵感默认折叠。

如果只说“这份攻略不满意”，顾问会先追问希望改善哪里；明确说“保留地点，把玩法和餐饮写详细”会更新攻略内容。修改失败会保留原有攻略并说明情况，不把失败伪装成已完成。普通问题仍然只回答，不自行替换路线。

## 搜索、正文与来源

DeepSeek 通过服务端的 search_travel_web、fetch_travel_page 工具检索和读取可访问的公开旅行资料。地点推荐可以超出纪念品和地图精选目录；新推荐地点必须关联本轮取得、包含地点名称的来源。每个来源保留网址、读取日期与状态。搜索摘要只是提及，不等于已读正文或保证营业信息准确。

支持的来源包括政府文旅页面及部分旅游／社区站点。小红书、点评等页面可能要求登录、验证或仅返回空壳；此时标记访问受限或不可读取，不绕过限制、不声称整合了所有攻略。可提供公开链接，也可在导入攻略中粘贴有权使用的正文。

每次顾问调用最多三轮、六次工具查询，有请求时限和网页体积限制；网页不能执行命令或改变系统规则。网络或资料读取失败时明确说明，保留旧方案。营业、票价、预约、菜单、天气和实时交通仍须临行确认。

后续追问可继续引用先前查到的资料，保留原读取时间并标注“此前查到的资料”。不能把搜索摘要当作已核实的预约政策，也不能把预算目标当作保证报价。

## 地图与行程

“从我的位置出发”按需请求高德定位；同意浏览器位置权限后，可点景点作为终点。拒绝权限、城市级粗定位或失败均显示说明，原路线保持。精确当前位置只用于当次地图比较，不存入需求、聊天或行程。

密度可选招牌地标、详细探索、只看行程；分类可选地标、购物、文化或公园。广州精选池 26 处，包括天环、正佳、天河城、太古汇；高德搜索可查目录外地点。点击建筑只查看和选起终点，明确点击加入／移出才改变行程。移除会同步必去与避开条件，后续规划不擅自加回。

需求区可改 1–7 天、每天 1–12 小时（半小时步长）和轻松／适中／紧凑。时间不足会说明冲突并保留旧方案。最后一站也能移除，空日保留为自由安排。手动新加地点的停留和转场是暂定估算，可继续向顾问细化。

对话可单独修改某天的时长、开始时间和强度；必去地点挤不进该日时会追问，不会偷偷删掉。调整全程天数会重置单日覆盖；调整全程时长或强度仅重置对应项。问“第二天玩两小时够吗”属于咨询，不会直接修改行程。

## 保存与当前限制

需求、行程与攻略存入当前浏览器的用户存档，最近12条对话单独保存；尚无跨设备同步。新方案会隔离旧需求，旧方案仍可展示，但需完成新方案后再编辑其地点。未配置 AI 时只提供本地示范。

预算是上限，不是已核实的整趟报价；日程中的停留和转场仍是估算，高德比较功能返回所选两点的实际查询结果，尚未把全程每段交通自动写回排程。预制纪念品只覆盖原目录，其他地点可通过照片定制。

## 实现与验证

travel-profile.js 合并确认与暂定需求；travel-schedule.js 检查每日容量与必去；travel-advisor.js 执行 DeepSeek 工具循环和攻略校验；travel-research.js 读取公开来源；travel-agent.js 保留路线与跨轮上下文。服务端默认启用顾问流程，旧版直接调用测试可关闭 advisorEnabled 验证兼容行为。

运行 npm test；浏览器回归包括 travel-understanding、travel-settings、travel-guide、travel-map-discovery、travel-map、travel-itinerary-edit、travel-map-camera-regression 与 travel-map-location-races。自动化用独立浏览器与模拟接口，不接触用户实际位置或存档；真实 DeepSeek 联调结果仅保存在忽略的 artifacts/map-advisor/。
